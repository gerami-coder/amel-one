# Verification
Run from amel-one: npm run lint, npm run typecheck, npm test, npm run build, npm run test:e2e. Playwright uses a production server and checks desktop, mobile and tablet. E2E_BASE_URL selects a hosted target; without it the runner starts localhost.

Sixteen unit tests cover permissions, lifecycle, contracts, required/select/checkbox/email answer validation, unknown answer stripping and publication readiness. Browser tests cover marketing/demo/auth validation/protected routes, authenticated persistence/logout and the complete create → types → form/reorder/undo → logo/branding → preview → publish → anonymous registration → search/detail/approval journey. They assert no page errors and no horizontal overflow. Authenticated tests require an ignored .test-fixture.json with a disposable development account; absent credentials mean explicit skips, not verification.

tests/database/registration-workflow.sql runs in a rollback transaction. It verifies draft privacy, stale versions/revisions, capacity, request replay, mandatory answers, immutable historical forms, status transitions, audit entries, anonymous read denial and cross-tenant read/update/delete/publish/review denial. It supersedes the Phase 0 direct-write tenant-isolation test because those writes are now revoked.

scripts/verify-registration.ts tests real concurrent API requests: four callers for one place yield exactly one success, parallel draft writes yield one HTTP 409, and drafts do not change the public snapshot. Both this helper and scripts/seed.ts require APP_ENV=development, SEED_PROJECT_REF matching the explicitly selected URL, no VERCEL_ENV, and --confirm=<project-ref>. Run with node --env-file=.env.local --import tsx scripts/verify-registration.ts --confirm=<project-ref> after setting SEED_PROJECT_REF. The fixture must be an example.test identity.

The seed creates African Business Expo 2027 demo with four types and 50 fictional registrations across pending/approved/rejected states. It is idempotent and never truncates data. No attendee email is sent. Screenshots/traces and fixtures remain ignored. See PHASE-1-REPORT.md for executed results and limits.
